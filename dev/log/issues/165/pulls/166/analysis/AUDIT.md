## Sequence of events

1. The issue listed ten normal workflows and one Dependabot update. C# was the only failed listed workflow. Its `macos-26` job queued at 2026-11-05 15:25:16 and was cancelled around 15:40:17 without a runner, steps or test execution. GitHub's annotation says: **The job was not acquired by Runner of type hosted even after multiple attempts.** Other C# matrix jobs passed. This is infrastructure capacity, not a failing assertion or an inadequate test timeout.
2. At issue creation (23:17:22), main was already `e183f0d`, after those listed runs. The prepared PR at `a20e071` exposed real dependency freshness failures and a Rust CodeQL upload failure. The Rust upload failure had no useful annotation or error in the available log; its historical cause remains unknown. Later fresh Rust CodeQL runs succeed. Debug output is now available for recurrence; this record does not invent an explanation for that historical event.
3. Initial source inspection and offline reproductions found gates that accepted failed prerequisites, dropped adjacent link failures, treated unavailable evidence as clean, or accepted extraction diagnostics with zero security findings. The first implementation commit, `f2d6054` (23:34:49 CI), made the hidden defects observable.
4. That CI exposed a forgotten runnable documentation Cargo lock, two tests that assumed repository-root working directory, and an undefined JavaScript workflow dispatch input. Those were repaired in `3433097`. It also exposed genuine extraction problems: valid awaited `using(...)` calls in JavaScript and multiple independent C# top-level example programs.
5. A focused debug rerun of C# CodeQL captured five CS8802 errors at lines 178356–178360 of `../ci-logs/codeql-csharp-debug.log` (stored compressed if `.gz`). Each example compiled as an independent program, but buildless analysis combined their top-level compilation units. Rewriting the five entry points as explicit, uniquely namespaced `Program.Main` methods preserved behavior and made C# CodeQL pass.
6. The JavaScript helper was renamed from `using` to `withClient`, preserving all call sites and conformance behavior. Nevertheless, run 42133108866 still reported the old extraction error. Its SARIF diagnostic carried `timeUtc=2026-11-05T15:25:47.384528128Z`, before the repair committed at 23:56. The log restored the main overlay database. This proves stale diagnostics were being reported; it does not prove which internal cache/diagnostic persistence layer is responsible. `CODEQL_OVERLAY_DATABASE_MODE=none` forces current-checkout extraction while the strict completeness gate stays enabled.
7. During the audit new NuGet releases appeared. The dependency gate correctly rejected six old references. All maintained production/example/experiment/documentation references were updated, including Platform.Data.Doublets 0.18.10 and Link.Foundation.Links.Notation 0.31.0. The next dependency run passed.
8. Full-tree comparison identified missing JS/Python formatting and lint/type checks. ESLint/Prettier now cover all maintained JS/JSX/helpers/examples; Ruff covers all maintained Python and mypy checks the runtime CI helpers. The added tooling initially resolved vulnerable minimatch; an override to patched 11.0.5 removed all npm audit findings. Python tool requirements receive freshness, Dependabot and resolved dependency auditing.
9. A synthetic credential in a Git-ignored `.log` reproduced another false negative: the existing secrets command skipped committed evidence. Git now provides the inventory, ignores cannot suppress tracked files, and compressed `.log.gz` evidence is decompressed and checked sequentially with a finite 128 MiB output bound. The regression checks both plain and compressed evidence and removes its synthetic fixture.

The generated `timeline.md` contains the complete collected run chronology, with links, creation times, SHAs and conclusions. A later successful run is never used to rewrite an older failure's meaning.

[CodeQL Action configuration](https://github.com/github/codeql-action/blob/main/src/config-utils.ts) accepts explicit overlay mode `none`. Source and diagnostic timestamps support the chosen extraction workarounds.
- [SARIF specification](https://docs.oasis-open.org/sarif/sarif/v2.1.0/os/sarif-v2.1.0-os.html) distinguishes results, invocation success and tool execution notifications; zero results alone cannot establish extraction completeness.
- [NuGet audit](https://learn.microsoft.com/en-us/nuget/concepts/auditing-packages) and [NuGet API-key verification](https://learn.microsoft.com/en-us/nuget/api/api-key-resource) support graph auditing and authentication verification; package publication authorization is a distinct assertion.
- [crates.io API source](https://github.com/rust-lang/crates.io) supports an authenticated invalid archive as a nonpublishing check; the helper regression tests require the expected authenticated rejection shape, not an arbitrary HTTP 400.
- [npm trusted publishing](https://docs.npmjs.com/trusted-publishers) informs the retained trust verification path. No PR test publishes or probes private credentials.
- [ESLint](https://eslint.org/docs/latest/use/configure/), [Prettier](https://prettier.io/docs/api), [Ruff](https://docs.astral.sh/ruff/), [mypy](https://mypy.readthedocs.io/en/stable/command_line.html) and [pip-audit](https://github.com/pypa/pip-audit) provide existing quality/audit engines. Native JSX support avoids an incompatible React lint plugin peer dependency. Patched minimatch is selected because the registry audit identified [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).
- [Secretlint ignore semantics](https://github.com/secretlint/secretlint/blob/master/docs/configuration.md) explain why `.gitignore` hid force-added evidence. The locked CLI uses `--no-gitignore --no-glob` on Git's inventory. Synthetic regression credentials are assembled at runtime and never committed.
- [lychee #2297](https://github.com/lycheeverse/lychee/issues/2297) already covers unanswered transport failures not being retried; its existing report is retained instead of duplicated. Existing template retry helpers supply the bounded implementation; no additional general retry library is needed.
- Official [upload-artifact](https://github.com/actions/upload-artifact) and [download-artifact](https://github.com/actions/download-artifact) remain the artifact transport components. The [Actions toolkit 6.3.0 release](https://github.com/actions/toolkit/releases/tag/%40actions%2Fartifact%406.3.0) records bounded HTTP 429 Retry-After handling; retrieved release evidence is in `../research/actions-artifact-releases.md`. Template custom SDK bundles are not copied as generated product dependencies; their integrity, missing-output and retry practices are compared against official action behavior.

## Verification and practical limits

The inexpensive local suite covers workflow/helper failures, registry mocks, Cargo warning/status handling, link and archive failures, SARIF completeness, NuGet graphs and runner recovery. Separate JS client unit tests and three-runtime backend conformance remain. Full native Rust/.NET/Wasm builds and OS matrices run on CI rather than in the 2.92 GiB development container. No artificial unbounded stack/memory probe is used.

`../verification` contains commands' actual logs. `reproduce-template-gaps.mjs` runs the old snapshotted helpers and repaired equivalents against identical bounded inputs: adjacent link records are dropped before and retained after; extraction-error SARIF passes before and fails after. `reproduce-ignored-secret.mjs` demonstrates the ignored-log false negative and the plain/compressed repair. Registry authentication and infrastructure recovery use mocks for denied/unknown/transient outcomes; no private credential is needed for PR validation.

The recovery workflow's `workflow_run` trigger becomes active only when it exists on the default branch. Its classification, pagination, newest-run guard, attempt cap, trusted checkout and refusal to retry executed failures are verified before merge; an actual future hosted-runner outage cannot be deliberately scheduled from an unmerged PR. Likewise, successful publication is not claimed: main must fail with actionable configuration instructions when the required credentials are absent. These are deployment semantics and explicit fail-closed behavior, not deferred implementation.

Final CI conclusions and exact head are recorded in the PR checks and final validation record. Evidence is collected at a finite audit cutoff: a later evidence-only commit does not retroactively alter historical run SHAs or outcomes.

At the evidence cutoff, all ten workflows passed on `fd17aa4ecc799435c5e70b16e5b0021489e20d2a`. All 43 collected runs retain complete available logs, metadata and job annotations. Local checks after archiving passed 275 CI/.NET helper and repository-layout cases, all 80 maintained JavaScript files, all 15 maintained Python files and strict typing of both runtime CI helpers. The before/after template and ignored-log/compressed-log secrets reproductions pass. Full final-head validation is required before marking the PR ready.

The baseline C# installer also prints GPG's standard warning that a downloaded signing key has no local web-of-trust certification (raw log line 4521). Signature verification succeeds; this is neither a failed signature nor a compiler/test warning. Trust is not globally relaxed to hide that third-party diagnostic. The independently actionable baseline Rust file-size warnings were removed by extracting all five near-limit modules/tests while preserving their APIs and cases.
