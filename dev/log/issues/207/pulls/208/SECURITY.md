# Committed-secrets CI follow-up

## Timeline and root cause

- The 14 workflows passed on `27d93ed1`. The next commit, `2e62057c`, was an automatic development-log publication that only changed investigation evidence. On that revision, 13 of 14 workflows succeeded. [Publishing commit](https://github.com/link-foundation/link-cli/commit/2e62057c38978d28d9bb8f9b2c3221bf5600781b)
- On November 28, Security failed. The scanner exited with zlib error `Z_DATA_ERROR` at [line 17 of the failed job log](github/46093593079.failed.log#L17), and the pipeline’s status job listed `secrets-scan (failure)` at [line 76](github/46093593079.failed.log#L76). All five CodeQL jobs and the dependency audits passed. [Actions run](https://github.com/link-foundation/link-cli/actions/runs/46093593079) · [Job metadata](runs/46093593079.json) · [Complete run log](../../../../../../docs/case-studies/issue-207/archives/runs/46093593079.log.gz)
- An integrity check found eight invalid gzip files for seven run IDs. Each damaged file began with `1f ef bf bd`. RFC 1952 defines the gzip signature as `1f 8b`; the second byte was replaced with the UTF-8 replacement character. Hive Mind 2.50.0 recursively reads regular files in the development-log directory as UTF-8 and rewrites any file that matches its credential patterns. A minimal gzip fixture with a synthetic token-shaped header comment reproduced the same byte change and zlib error. [Archive inventory](verification/security/gzip-errors.log) · [Reproduction output](verification/security/hive-gzip-reproduction.log) · [Hive Mind #4188](https://github.com/link-assistant/hive-mind/issues/4188) · [RFC 1952](https://www.rfc-editor.org/rfc/rfc1952#section-2.3.1)

## Recovery and verification

- The archive contains complete logs from all 14 workflows for `2e62057c`. The corresponding [run metadata](runs) records each tested revision, job result and timestamp.
- The previous Git revision preserved five valid copies in `runs/`. GitHub Actions supplied the three copies in `ci-logs/runs/`. All recovered archives stay in Git under [the case-study archive directory](../../../../../../docs/case-studies/issue-207/archives). Node 26’s recursive directory listing traversed a test directory symlink and Hive Mind reproduced the gzip damage through it, so the evidence index uses Markdown links. The secret scan finds the archived files through Git and checks their decoded content.
- The scanner reports the path and underlying zlib cause for invalid `.gz`, `.tar.gz` and `.tgz` files. `.tgz` now enters the same tarball scan as `.tar.gz`. The regression test fails on the original scanner. Existing and new secret-positive tests check that the scanner rejects a synthetic match inside a valid archive. [Before](verification/security/local-test-before.log) · [After](verification/security/local-focused-after.log) · [Regression test](../../../../../../.github/scripts/check-secrets.test.mjs)
- A repository exclusion would allow unreadable or unscanned evidence to pass. Recovered archives retain the existing decompression cap and fail on malformed data. The upstream report proposes format-aware preservation and bounded decompression using Node’s existing zlib API. [Node.js zlib options](https://nodejs.org/api/zlib.html#class-options) · [Hive Mind #4188](https://github.com/link-assistant/hive-mind/issues/4188)
