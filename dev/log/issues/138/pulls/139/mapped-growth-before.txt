The isolated Linux child ignores SIGXFSZ and inherits an 8192-byte soft file
quota, a 128 MiB managed heap cap and disabled runtime memfd code mappings.
The parent reaps it after a finite deadline. Files are at most three 4 KiB pages.
After writing and flushing one page, requesting three pages is rejected. The
base keeps its 4096-byte reservation and old pointer, but the callback already
disposed the old mapping and stream. Flush fails before the test reads that
unsafe pointer. The separate ordinary-growth/invalid-capacity control passes.

The first draft expected only IOException for EFBIG and overestimated Unix
FileShare.Read enforcement. Those test oracles were corrected before the actual
product failure above: accept the runtime's ArgumentOutOfRangeException too,
and check denial of an exclusive file handle on every supported platform.
The initial two-failure run is not counted as product reproduction evidence.

The base setter was traced in installed Platform.Memory 0.4.1 source, commit
dd464b7b48a4efcaa90fcbaf0621944c184611fd. Capacity is published only after the
resize callback returns. No upstream source modification is required.
