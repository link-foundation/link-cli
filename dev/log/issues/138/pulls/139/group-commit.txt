Independent-session group commit (2026-10-25)

Reproduction:
The new group API was first implemented temporarily by calling ordinary commit
for each member. Rust and C# two-session tests fail: expected one flush, actual
two. This is a prototype baseline, not an older production group API.
Preserved: group-commit-rust-before.txt, group-commit-csharp-before.txt.
Separately, existing synchronous replication flushes the primary twice during
one flush call. All three implementations fail before the correction; preserved
in group-replication-{rust,csharp,js}-before.txt.

Implementation/guarantee:
Validate existing sessions in input order against private tentative state;
append each accepted writer's own revision, flush once, then publish under the
engine gate. Known aborts stay aborted. Unknown append/flush outcomes fence the
engine and leave its old visible state; every provisionally accepted member is
indeterminate. Reopening discovers a valid prefix. The group is not atomic.
Ordinary commits acquire no timer, worker, queue or automatic delay.
Synchronous replication now flushes each copy once; explicit catch-up still
flushes the primary. Buffered append is necessary to amortize per-append fsyncs.
