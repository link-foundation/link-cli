Cause: the new discovery-only device uses InvalidDataException for a missing
physical data image. C# mirror recovery recognizes IOException read failures;
InvalidDataException is outside that inheritance tree. A complete surviving
mirror therefore cannot supply its page during the read-only validation pass.
Use EndOfStreamException, matching the underlying physical short-read contract.
Do not broaden the existing mirror's exception handling or perform early repair.

The regression also corrupts both copies of a later selected table and checks
every existing file byte and missing filename before restoring it. Only after
the complete selected state validates may recovery create the missing redundant
files and repair them from the surviving copy. Separate controls retain a valid
plain metadata slot and defer mirrored repair on later binding failure.
