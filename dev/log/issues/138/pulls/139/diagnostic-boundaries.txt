Diagnostic I/O regression and finite boundary verification (2026-10-24)

Before: e2e714f, newly added Linux subprocess regression, before implementation
  cargo test --manifest-path rust/Cargo.toml --all-features \
    --test engine_boundary_tests unavailable_diagnostic_output -- --nocapture
  commit: child exit status: 101 after persisting 1 rows
  replication: child exit status: 101 after persisting 1 rows
  test result: FAILED. 0 passed; 1 failed; 0 ignored

Fault: the child inherits /dev/full as stderr. Each write fails immediately with
ENOSPC; the experiment never fills a disk. A read-only stderr probe does not
reproduce this bug because Rust ignores EBADF. This regression is Linux-only.
Other platforms still run the portable recovery and storage contract tests.

Root cause: opt-in eprintln! calls panic after successful engine publication or
replica work. Use fallible writes for diagnostics and discard only that result.
Storage errors retain their existing propagation and poisoning behavior.

Finite counter/recovery tests additionally check valid-checksum but invalid
journal sequences, forged saved merge bases, pending-session log fencing,
u128/UInt128 allocation exhaustion, revision exhaustion, poisoned engine mutex
extraction, and closed read-committed visibility. Adapter contracts check
callbacks/errors, optional query filters, borrowed reads, external sidecar
changes, flush retry and deterministic pinned addresses. Network fixtures check
actual custom headers, malformed headers, and failed object staging without
catalog publication. Counter limits are set directly in tiny private fixtures;
no test loops to an address or revision limit.
