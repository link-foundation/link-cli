## Template crosswalk

| Practice | Template implementations and link-cli decision |
| --- | --- |
| Preserve independent runs | All six templates had branch-scoped cancellation for one or more read-only checks on default-branch pushes. Rust, JS and Python had previously chosen that behavior. C# and C++ already separate writers. link-cli applies the newer guide’s event/revision policy across all sixteen workflow files and enables the existing upstream writer queue pattern. |
| Run cheap checks first and prove their provenance | Rust and JS contain JavaScript-first examples and policy helpers. link-cli requires a same-commit reusable stage and validates a golden-fixture receipt per language. Workflow policy caps job timeouts at 30 minutes, with named limits for native builds and registry waits. Python, Java and C++ examples assume standalone distributables and toolchains. Their language-specific release steps do not apply to the port and fixture code in this monorepo. |
| Validate scope and fixtures | The templates use change detection, fresh-merge checks, and size and docs gates. link-cli already uses whole-PR comparisons, fresh-merge simulation, conditional native jobs, strict required status, parity and explicit layout checks. The JS package path filters in this PR now include the shared stage, internal examples and all conformance inputs. |
| Keep full verification on the current PR revision | The guide offers a ready-for-review trigger paired with a separately required full-tier status. This repository requires JavaScript, Rust and C# pipeline statuses on every PR revision. It runs the applicable native jobs after the shared JavaScript stage and keeps the full check current on each synchronization. The path rules encode the small set of package dependencies and shared CI inputs. |
| Keep releases independently recoverable | Rust uses crate preflight and ordered Git/registry publication. C# includes NuGet authentication/fallback and package verification. The JS template checks the published package separately. Here the npm tarball gate becomes credential-free, the main writer retains npm provenance and trusted publishing, and a separate job downloads the published version with a clean npm cache and configuration. The client download succeeded locally and the server's exact-version download reproduced HTTP 404. PyPI, Maven and vcpkg release examples target different outputs. |
| Match runnable targets and runner capacity | The container-image guidance applies when repository workflows build and distribute container images. link-cli releases native binaries and language packages. Its pinned native runners build the platform artifacts directly. Native suites use matrix jobs and keep the dependency order for shared fixtures, compiler output and cross-language tests. |
| Audit workflow and dependencies | Templates combine CodeQL, Actionlint, zizmor, lockfiles and secret scans, with tool-specific differences. link-cli already lints embedded shell code, keeps namespace pinning rules, scans historical evidence and runs CodeQL, dependency review and package ecosystem audits. Template Actionlint workarounds use a narrow exception or preprocess supported queue syntax. link-cli pairs a narrow diagnostic exception with a local queue policy check. |
| Recover runner and link infrastructure | Templates use bounded reruns for unacquired runners and recheck intermittent links. link-cli already distinguishes unacquired jobs, protects active writers, and rechecks transient links with archive evidence. A test process cancelled during execution is a different failure and is addressed in the concurrency keys. |
| Account for external changes and skipped jobs | The repository already reports dependency freshness on main pushes, enforces it on PRs and in scheduled checks, and tracks enforcement failures as issues. Dependabot configuration covers existing package ecosystems. Pipeline status checks report skipped jobs and reject a failed or cancelled prerequisite. Registry diagnostics in this PR distinguish missing setup from an inconclusive lookup. |
| Keep the repository maintainable | C#, Rust, Python, Java and C++ have hook configurations and language-specific size or static checks. JS adds package size and fast lint scripts. link-cli mirrors CI checks in its hook definitions and uses a lower warning threshold than its hard size limit. |

### Remaining registry action

`https://registry.npmjs.org/@link-foundation%2Flink-cli-server` returned 404 for anonymous metadata, while the client package returned 200. A scope maintainer can validate the tarball with `cd js/server && npm pack --dry-run`, publish the initial public version from a reviewed revision or make the existing package public if it is private, and open the npm package’s **Settings → Trusted publishing**. Select GitHub Actions, set the owner to `link-foundation`, repository to `link-cli`, and workflow filename to `js-server.yml`. Permit direct publication because this workflow uses `npm publish`. Run **JS server CI → Run workflow** on `main` with **Verify npm trusted publishing** enabled, then retry the main workflow. npm currently requires a new configuration to complete a successful trusted publish within two days. Consult npm’s setup and scope documentation for the first-publish or staged approval procedure. [npm trusted publishing](https://docs.npmjs.com/trusted-publishers/) · [npm scoped packages](https://docs.npmjs.com/creating-and-publishing-scoped-public-packages/) · [npm access](https://docs.npmjs.com/cli/v11/commands/npm-access/)

### Provider diagnostics and design alternatives

- **Node FFI and LLVM branch coverage.** Node labels the direct `node:ffi` backend experimental. `cargo-llvm-cov` similarly reports the experimental LLVM branch mode on stable. The real FFI backend and branch coverage remain enabled. Switching to native Node-API bindings or dropping branch coverage would change the packaging or verification contract. The workflows preserve those lifecycle messages. [Node v26 FFI](https://nodejs.org/docs/latest-v26.x/api/ffi.html) · [cargo-llvm-cov](https://github.com/taiki-e/cargo-llvm-cov)
- **Codecov and Dependabot.** Codecov’s PGP verification prints the key trust-database advisory alongside a good signature and verified checksum. Dependabot’s managed environment rehashes a bundled CA file and reports that it contains several certificates. The relevant upload and managed jobs completed. [Codecov wrapper](https://github.com/codecov/wrapper) · [OpenSSL rehash](https://docs.openssl.org/3.5/man1/openssl-rehash/)
- **Codecov GitHub integration.** The coverage comment on PR #208 reported full coverage of modified coverable lines and asked for the Codecov GitHub App. The organization installation list contained no Codecov entry. Installation grants the integration write access to checks, status and pull requests and needs an organization owner’s approval. The existing coverage uploads and coverage checks run independently of that installation. [Codecov report](https://github.com/link-foundation/link-cli/pull/208#issuecomment-7228504998) · [Codecov GitHub App](https://github.com/apps/codecov)
- **Concurrency tooling.** GitHub job concurrency is sufficient for repository writers. A local action or custom lock service would not protect jobs pending on independent runners. The pinned Actionlint release still treats the documented queue property as unknown. The exception matches that diagnostic only and policy tests enforce its allowed placement and value. [GitHub concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) · [Actionlint #657](https://github.com/rhysd/actionlint/issues/657)
- **Election observation.** The etcd v3 maintenance endpoint already supplies member, leader and term. Polling it while the original process is stopped provides direct evidence without a new client dependency or an arbitrary election sleep. [etcd maintenance API](https://etcd.io/docs/v3.6/dev-guide/api_reference_v3/#service-maintenance-etcdserveretcdserverpb-rpc-proto)
- **Windows ring ownership.** The JS descriptor closes before its deletion attempt. The native peer can retain its mapped view while it processes the hangup. Windows denies deletion of an active mapping, and Node 26.13.1 reports that permission error as `EPERM`. Both native implementations close their views before attempting removal, so the JS client returns from teardown on Windows sharing errors and lets that peer remove the file. Fixed-delay retries would keep the JS stream open and still depend on when the peer releases its view. The existing `CLINK_IPC_TRACE=1` toggle records when deletion falls to the peer. [IPC protocol](../../protocol/ipc-transports-v1.md#rendezvous-directory) · [Windows file disposition](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_file_disposition_information_ex#remarks) · [Node 26.13.1 removal](https://github.com/nodejs/node/blob/v26.13.1/src/node_file.cc#L1895-L1925)
- **Windows PID-lock cleanup.** The lock is released by moving its directory and removing the private tombstone. A waiter can still have the directory’s owner file open when the holder tries to move it. Windows documents that an open child handle can prevent a rename. The failed run recorded the leftover entry but omitted its basename and Windows error, so an exact failing operation cannot be recovered from that log. Bounded retries cover transient permission and sharing errors during release and private-directory cleanup. C# owner reads now use the same sharing flags as native Rust and Node. Existing trace flags disclose exhausted cleanup retries. [Windows rename rules](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information#remarks)
- **C# restart-fixture setup.** The outer xUnit deadline exposed no last operation. Each case formerly paid for the same process launch, durable setup and abrupt exit before reaching the fault under test. A single real crash image supplies twelve identical starting states. Each case mutates its own copy, and the separate movement suite still generates real abrupt exits at all persisted phases. The original 30-second test limit remains in force. With `LINK_CSHARP_RECOVERY_TRACE=1` or repository variable `CI_VERBOSE=true`, the restart tests record their last completed phase, elapsed time and queued work.
- **Historical CodeQL configuration.** GitHub’s PR summary expects the former C# autobuild category, last uploaded to `main` on 2026-10-24. Commit `cfd03518` switched C# to buildless analysis that day. Both the current base and PR contain successful scans for all five configured languages. GitHub still returns a neutral comparison because 23 historical analyses remain under the old category. GitHub’s documented cleanup removes that stored configuration from `main` and requires approval to delete the historical analysis. [PR comparison](https://github.com/link-foundation/link-cli/runs/140777680942) · [GitHub configuration cleanup](https://docs.github.com/en/code-security/how-tos/manage-security-alerts/manage-code-scanning-alerts/resolve-alerts#removing-stale-configurations-and-alerts-from-a-branch)
