# Atomic replacement over two fixed page banks

This optional protocol adds complete ordered-journal replacement to the existing
[native pages](native-pages.md). Ordinary page and metadata bytes are unchanged.
Rust `CheckpointPagedLog<R, D>`, C# `CheckpointPagedCommitLog` and the separate JS
`engine-checkpoint-pages` entry implement the same wire format. Independent
[vectors](checkpoint-pages-v1.json) are generated by
`experiments/issue-138/make-checkpoint-page-vectors.py`, without production codecs.

The caller provides one root device and two page-bank devices under a single
exclusive owner. Root data stays empty. Each device has two metadata slots;
single-copy banks use flags zero and mirrored banks use flags one. By default the
root is raw. Optional [root mirroring](checkpoint-root-mirror.md) uses a distinct
checkpoint adapter over two raw devices, independently of bank mirroring.
Both persisted modes stay fixed for the store's lifetime. All handles stay open through
replacement. Internal bank paths must not be opened independently. Acquire root
ownership before bank ownership and release root ownership after all banks.

## Root record

Every root decision is exactly 128 bytes, with little-endian integers:

| Offset | Bytes | Field |
| --- | --- | --- |
| 0 | 8 | ASCII `CLNKBK01` |
| 8 | 16 | Root identity |
| 24 | 8 | Unsigned 64-bit epoch |
| 32 | 4 | Bank index, `epoch % 2` |
| 36 | 4 | Bank mode bit 0 and optional mirrored-root bit 1; values 0–3 |
| 40 | 16 | Exact derived bank identity |
| 56 | 64 | Zero reserved bytes |
| 120 | 8 | FNV-1a-64 checksum of bytes 0 through 119 |

Checksum constants match native metadata. A bank identity is the root identity
XOR the concatenation of the eight little-endian epoch bytes and ASCII `BANK0001`.
For one root this produces a distinct identity for every possible epoch, even
when the device entropy provider always returns the same identity. It is an
equality/version binding, not authentication.

A valid decision must occupy slot `epoch % 2`. Two valid decisions must share
one root identity and have adjacent epochs. Select the higher complete epoch;
validate that selected bank's metadata identities and entire committed prefix
before recovery writes. Checksummed unsupported versions, padding, flags, bank
indices, identities or conflicting roots reject opening. Invalid length or
checksum is an interrupted decision and permits selecting the other valid root.
Damage to the selected committed bank rejects opening; an older root is not
permission to discard its acknowledged records.

With no valid root, initialize only banks with no physical data and no valid
nonempty committed metadata. Partly initialized single-copy empty banks can be
reset. Mirrored devices retain their stricter metadata-conflict rules. Unknown
or nonempty unrooted journals require recovery; initialization never erases them.

## Replacement order and failure model

1. Validate every input record and page quota. Reject pending physical appends.
   Reading an identical committed sequence returns false without bank/root
   rewrites. Read validation can perform selected mirrored repairs.
2. Check the epoch increment, then fence this owner before changing storage.
3. Truncate and synchronize the inactive bank. Write and synchronize both empty
   bank metadata slots with the new epoch identity.
4. Use the unchanged page protocol to write the complete replacement group,
   synchronize all its data copies and publish its bank metadata decisions.
5. Write the new root into its alternate slot and synchronize that slot.
6. Adopt the prepared bank and return true. Retain the former bank for the next
   replacement. No page or metadata in the selected old bank was overwritten.

Any error after reading/persistence begins fences the owner until actual reopen.
An invalid input or exhausted epoch rejects before writes and leaves it usable.
At epoch `2^64 - 1`, ordinary append/flush and identical replacement remain valid;
another differing replacement rejects. JS exposes epochs as `bigint`.

Under truthful device synchronization and a crash that preserves previously
durable bytes outside subsequent writes, every interrupted replacement reopens
the complete old or complete new sequence. Unacknowledged root writes may have
persisted; reopening discovers their outcome. Finite tests inject errors before
and after each baseline physical operation, including mirrored copies, then
reopen independent durable images and perform another replacement and append.
They also test all 128 truncated-root lengths, stale valid bank metadata,
selected-bank corruption, initialization failures and 64-bit boundaries.

These are device-model/process assumptions, not hardware power-loss evidence.
Alternating root publication does not repair arbitrary later root-media damage.
Mirrored banks repair their selected epoch only after full-prefix validation.
Two corrupt root slots with nonempty banks reject recovery. Initial file-name
durability remains a native device/platform responsibility; replacement itself
does not create, rename or replace pathnames. The decision design avoids the
open-handle and directory-ordering costs described by [rename(2)](https://man7.org/linux/man-pages/man2/rename.2.html)
and [fsync(2)](https://www.man7.org/linux/man-pages/man2/fsync.2.html).

## API and costs

The optional replacement capability preserves the ordinary ordered-log API:
Rust `ReplaceableTransitionLogStore::replace_log_entries`, C#
`IReplaceableCommitLog.Replace` and JS `replace(records)` return a boolean after
publication. Input strings preserve exact UTF-8, including BOM, NUL and Unicode;
CR/LF and malformed UTF-16 reject. Empty replacement is supported. C# and JS
leave device cleanup with the caller. Rust consumes its device values; automatic
destruction drops both banks before the root and follows each supplied device's
destructor. Rust `into_devices` restores canonical bank order and transfers
cleanup responsibility: explicitly release both returned banks before the root.
Neither extraction nor destruction flushes staged records. External writer
fencing remains with the device owner.

Replacement scans O(old committed bytes) for the identical-sequence check and
uses O(replacement bytes) pending buffers plus the normal page buffer. It writes
O(replacement bytes/pages), two empty 128-byte bank decisions, a complete bank
decision, and one 128-byte root. Mirroring doubles bank I/O. Two bank images
occupy disk until a later replacement reuses the inactive bank. Default ordinary
journals incur no root device, second bank or replacement work.

## Engine publication

Rust `Engine::compact_journal`, C# `LinksEngine.CompactJournal` and WASM/JS
`WasmEngine.compactJournal()` construct the same retained committed records as
checkpoint export, holding the commit mutex continuously through replacement.
Select a replacement-capable log explicitly. Rust exposes the method when the
log implements `ReplaceableTransitionLogStore`; an implementation reporting
unsupported capability rejects before mutation. C#/WASM ordinary logs also
reject before mutation and remain usable for following commits. WASM external
logs opt in with exactly `supportsReplacement: true`; `replace(records)` must
finish synchronously and return a boolean. An identical sequence returns false.

Compaction does not advance the revision or alter retained snapshots, pinned
images, conflict generations, locks, admission counts or pending transactions.
Private allocator reservations remain reserved in the live owner and stay out of
the checkpoint. An independently reopened copy starts at the committed allocator
position. Branch merge-base descriptors retain their exact committed metadata.

Any replacement error can hide completed publication. The engine fences itself
and pending sessions until a fresh owner reopens storage and discovers the old
or new decision. Pinned immutable snapshots remain readable. Physical delta
decorators delegate the optional capability, validate and encode the entire new
sequence in temporary memory before inner I/O, and adopt their new codec state
only after a boolean acknowledgement. An uncertain replacement fences the codec.

Construction costs O(retained committed snapshot bytes); delta adds another
prepared physical sequence. This explicit operation holds the commit mutex for
construction, validation and storage synchronization. Ordinary commits do no
replacement work. See the finite [72-case example](../../examples/journal-checkpoints/compact.mjs)
and [native factories, recovery checks and file costs](../ENGINE-NATIVE-CHECKPOINTS.md).


## Read-only prefix inspection

Before higher-level manifest validation, select the committed physical prefix
without opening a recovering WAL: Rust `CheckpointPagedLog::inspect(&mut root,
&mut banks, max_pages)`, C# `CheckpointPagedCommitLog.Inspect(root, first, second,
maxPages)` and JS `CheckpointPagedCommitLog.inspect(root, banks, { maxPages })`.
The same exclusive device ownership and root/bank modes apply. Rust borrows the
devices; C#/JS retain caller ownership. All results contain owned strings.

Inspection validates root decisions, selected epoch identity, metadata conflicts,
page bounds, complete page chains, records and checksums. Missing or damaged
selected state fails without fallback. Empty or partially initialized zero-page
banks return no records without allocating an identity or completing creation.
Unrooted nonempty banks reject. A finite uncommitted suffix remains untouched;
inspection never truncates, synchronizes, initializes or completes repair.

Checked mirror reads can stage volatile repair state. If semantic validation of
the records and every selected table fails, discard those wrappers without
calling CompleteRecovery. After validation succeeds, ordinary opening revalidates
the prefix and performs its existing repair/truncation behavior. The native LSM
facade must hold one exclusive outer owner throughout both passes. This primitive
does not acquire directory ownership, enumerate files or validate an LSM manifest.
Its O(selected pages + record bytes) reads and owned-result memory are bounded by
the selected page limit; callers must select a limit suitable for their budget.
